# Release signing

Android keeps the app's data on an update only if the new build has the same application id (`com.candice.momspace`) and is signed with the same key. Every build that goes onto Mom's phone is signed with one release keystore. If the keystore or its password is lost, the app must be uninstalled and she loses her progress (`allowBackup` is off).

The keystore and passwords never go into this repository. `*.keystore`, `*.jks` and signing property files are git-ignored.

## 1. Create the keystore (once)

```sh
mkdir -p ~/Keys/momsaces
chmod 700 ~/Keys/momsaces
keytool -genkeypair -v \
  -storetype PKCS12 \
  -keystore ~/Keys/momsaces/momsaces-release.keystore \
  -alias momsaces \
  -keyalg RSA -keysize 2048 \
  -validity 10000
chmod 600 ~/Keys/momsaces/momsaces-release.keystore
```

`keytool` asks for a store password and the name fields. With PKCS12 the key password is the same as the store password. Never run this command again for this app: a new keystore means a new key.

Check the keystore and write down its SHA-256 fingerprint:

```sh
keytool -list -v -keystore ~/Keys/momsaces/momsaces-release.keystore -alias momsaces | grep SHA256
```

## 2. Give Gradle the signing properties

Put these in `~/.gradle/gradle.properties` (in your home folder, not in the repo):

```properties
MOMSACES_RELEASE_STORE_FILE=/Users/<you>/Keys/momsaces/momsaces-release.keystore
MOMSACES_RELEASE_STORE_PASSWORD=<store password>
MOMSACES_RELEASE_KEY_ALIAS=momsaces
MOMSACES_RELEASE_KEY_PASSWORD=<store password>
```

```sh
chmod 600 ~/.gradle/gradle.properties
```

Instead of the file, you can set environment variables. Gradle reads `ORG_GRADLE_PROJECT_<name>` as the property `<name>`:

```sh
export ORG_GRADLE_PROJECT_MOMSACES_RELEASE_STORE_PASSWORD='<store password>'
```

## 3. How the build uses them

`android/` is generated by `npx expo prebuild` and is git-ignored, so it is never edited by hand. The config plugin `plugins/withReleaseSigning.js` (added in task 6.7a and listed in `app.json`) writes a `release` signing config into `android/app/build.gradle` during prebuild. That config reads the four properties above. `prebuild --clean` therefore keeps signing working. If a property is missing, the release build stops with a message naming it.

## 4. Back up (do this straight after step 1)

1. Copy `~/Keys/momsaces/momsaces-release.keystore` to two places outside this computer, for example an encrypted USB stick and a password manager that stores file attachments.
2. Store the store password, the alias (`momsaces`) and the SHA-256 fingerprint in the password manager next to the file.
3. Test the backup: copy the keystore back from the backup to a temporary folder and run the `keytool -list` command above on that copy with the saved password. The fingerprint must match.

## 5. Build and install a signed release (task 6.8)

```sh
# 1. Bump android.versionCode (and version if needed) in app.json
npx expo prebuild --clean --platform android
(cd android && ./gradlew assembleRelease)
apksigner verify --print-certs android/app/build/outputs/apk/release/app-release.apk   # SHA-256 must match the recorded fingerprint
adb -s <serial> install -r android/app/build/outputs/apk/release/app-release.apk
```

`apksigner` is in the Android SDK build tools (`$ANDROID_HOME/build-tools/<version>/apksigner`).

A debug build is signed with a different key. If a debug build is on her phone, it must be uninstalled before the first release install, which deletes its data. Do this before she starts using the app.
