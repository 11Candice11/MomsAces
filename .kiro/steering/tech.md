# Tech

## Stack
- Expo with a development build (`expo-dev-client`). NOT Expo Go.
- **Pinned versions** (see "Pinned versions" below). Do not upgrade any of them without an explicit task.
- **Gate:** task 1.9 must pass `npx expo-doctor` and start a development build on a device or emulator before anything else is built on top. If MMKV v4 or Nitro causes any problem, stop and tell the owner, and propose AsyncStorage behind the same `services/storage.ts` adapter. Never work around it silently.
- No OTA updates (no `expo-updates`). Builds are installed over the existing app with the same application id (`com.candice.momspace`) and the same release signing key so her data is kept.
- `android/` and `ios/` are generated by prebuild and git-ignored. Never hand-edit them: native changes go in `app.json` or a config plugin in `plugins/`. Release signing reads Gradle properties from `~/.gradle/gradle.properties` or environment variables through `plugins/withReleaseSigning.js` (task 6.7a, `docs/release-signing.md`); the keystore lives in `~/Keys/momsaces/`, never in the repository.
- TypeScript, `strict: true`.
- React Navigation: bottom tabs (Home, Move, Play, Rewards) plus native stack for flows (Stand With Help, Exercise Session, Solitaire, Settings).
- Zustand with `persist` middleware, backed by `react-native-mmkv` (v4 API: `createMMKV`, `remove`) through a small adapter in `src/services/storage.ts`.
- Styling: plain `StyleSheet` driven by tokens in `src/theme`. Keep tokens structured (colors, typography, spacing, radii, touch) so NativeWind could be adopted later.
- Animation: `react-native-reanimated`, `react-native-gesture-handler`, `lottie-react-native`.
- Notifications: `expo-notifications` (local only). Water and Bathroom have "Done" and "Later"; Stretch and Stand have "Start" and "Later".
- Clock format: `expo-localization` (added in task 5.1) tells the app whether the phone uses a 12-hour or 24-hour clock. Formatting is the pure `formatTime(time, '12h' | '24h')` in `src/domain/shared` (R2.22).
- Copy check: `npm run check:copy` (added in task 15.4) fails if the word "streak" appears in any bundled copy (G11).
- Calling the helper: `Linking` (`tel:`, optionally `wa.me`).
- Tests: Jest (jest-expo or ts-jest) for pure logic only.
- Tooling: ESLint, Prettier, path alias `@/` -> `src/`.

## Architecture
```
src/
  theme/ strings/ domain/ store/ services/ navigation/ screens/ components/ assets/ data/
```
- **Pure logic lives in `src/domain` with NO React, React Native, Expo or MMKV imports.** Domain functions are pure and take time/random seed as arguments (no hidden `Date.now()` or `Math.random()`).
- Domain modules: `solitaire` (incl. solver and winnable-seed picking), `rewards` (incl. `economy.ts` and seedable mystery prize selection), `progression` (rank, path, Royal Flush, "days this week"), `reminders`, `tasks`.
- **`src/domain/rewards/economy.ts` holds every reward number, cost and price.** No other file repeats them; code and tests import from it. `src/data/prizes.ts` and `src/data/collection.ts` take their numbers from it.
- Stand countdown limits live in `src/domain/tasks/standCountdown.ts` (`STAND_COUNTDOWN`: min 15, max 60, default 30; her physio should confirm the range).
- Mockups are in `.kiro/docs/designs/`. They are visual references only; where their wording or behaviour differs from the spec, the spec wins.
- `src/data/winnableSeeds.ts` is generated by `scripts/generateWinnableSeeds.ts` (run with `npm run seeds:generate`). Never edit it by hand. Bump `DEAL_ALGORITHM_VERSION` whenever `shuffle` or `deal` changes, then regenerate. A seeded RNG is shared in `domain/shared`.
- **Celebrations and the mascot go through the shared components** in `src/components/celebrations` and `src/components/mascot`. Screens call `celebrate(...)` and render `<Mascot />`; no one-off animation code in screens.
- **Motion**: durations, easing and effect counts are theme tokens (`src/theme/motion.ts`). Animations read them only through `useMotion()`, which scales them for Calm mode and the system reduce-motion setting.
- Rewards are saved to the stores before any celebration plays. Celebrations are presentation only.
- Static data tables (`src/data`): `exercises`, `collection`, `prizes`, `medals`.
- `store/` wraps domain logic with Zustand and persistence.
- `services/` is the only place that touches platform APIs (notifications, Linking, MMKV).
- `screens/` and `components/` contain UI only. No game or reward rules in components.
- Platform-specific code (Android channels, exact alarms, battery settings) is isolated in `services/` behind `Platform.OS` checks so iOS can be added later.

## Data rule
- 100% local. No backend, no accounts, no network calls, no analytics, no crash-reporting SDKs.
- Do not add dependencies that make network calls.
- All persisted state is versioned (`persist` `version` + `migrate`).

## Conventions
- Named exports; one component per file; files in PascalCase for components, camelCase for modules.
- No `any`. Use typed navigation routes.
- Fonts: Playfair Display (headings), Nunito (body), bundled locally.
